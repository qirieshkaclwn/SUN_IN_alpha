## 1. Обоснование темы

### Выбор темы
**Тема проекта:** Разработка защищённого веб-мессенджера со сквозным (E2E) шифрованием, инфраструктурой открытых ключей (PKI) и WebSocket-транспортом.

### Актуальность
В современном цифровом мире вопросы информационной безопасности распределённых коммуникаций имеют первостепенное значение:
- **Конфиденциальность сообщений** — обеспечение невозможности перехвата и расшифровки данных третьими лицами и оператором сервера.
- **Аутентификация участников** — надежная защита от атак подмены личности (impersonation attacks).
- **Инфраструктура открытых ключей (PKI)** — общепринятый мировой стандарт верификации идентичности через цифровые сертификаты.
- **Доступность из веб-среды** — исполнение клиента в браузере без установки стороннего ПО за счет аппаратного ускорения **Web Crypto API**.

### Почему выбран данный подход
1. **E2E-шифрование (End-to-End)** — сообщения шифруются у отправителя и дешифруются только у получателя; сервер является исключительно недоверенным маршрутизатором пакетов.
2. **PKI с приватным Root CA** — сервер выступает в роли доверенного удостоверяющего центра, выпускающего подписанные X.509 сертификаты.
3. **Challenge-Response аутентификация** — сервер проверяет владение закрытым ключом через одноразовый криптографический nonce без передачи самого ключа по сети.
4. **Гибридное шифрование** — сочетание высокой производительности симметричного алгоритма **AES-256-GCM** и криптостойкости асимметричного **RSA-OAEP SHA-256**.

### Почему такая архитектура

| Компонент | Выбор | Обоснование |
|---|---|---|
| **Сетевой протокол** | WebSocket (RFC 6455) | Полнодуплексный двунаправленный протокол реального времени, встроенный в современные браузеры. Устраняет необходимость сырых TCP-сокетов с 4-байтными префиксами. |
| **Формат пакетов** | JSON фреймы (UTF-8) | Простота отладки, стандартизированность в веб-среде, расширяемость структуры данных. |
| **Frontend (Web)** | HTML5 + CSS + JavaScript | Отсутствие промежуточного web-gateway. Прямое подключение к серверу через нативный браузерный **Web Crypto API** (`window.crypto.subtle`) и `@peculiar/x509`. |
| **Backend** | Python (библиотека `websockets`) | Высокая производительность, многопоточная обработка клиентов, встроенный центр сертификации и одновременная раздача статики. |
| **Database** | PostgreSQL 16 | Надёжность, ACID-транзакции, аппаратная гарантия правила «1 сертификат на 1 ник» через `PRIMARY KEY`. |
| **Crypto** | `cryptography` (Python) + Web Crypto API (JS) | Сертифицированные, audited реализации современных криптографических стандартов. |
| **Контейнеризация** | Docker + Docker Compose | Полная изоляция окружения, запуск сервера и БД одной командой, встроенный healthcheck. |

### Паттерны проектирования
1. **Thread-per-Client**: обработка каждого WebSocket-подключения в отдельном легковесном потоке сервера с потокобезопасной отправкой (`_send_lock`).
2. **Repository / Active Fallback**: модуль работы с БД проверяет соединение и при отсутствии PostgreSQL автоматически переключается в in-memory кэш без сбоя сервера.
3. **Hybrid Cryptography**: разделение каналов шифрования данных (симметричный AES) и шифрования ключей (асимметричный RSA).

## 3. Описание архитектуры ПК

### 3.1 Компоненты системы

#### 3.1.1 Фронтенд (Пользовательский интерфейс)

**Web Client** (`client/index.html`, `client/app.js`, `client/x509.js`)
•	Интерактивный веб-интерфейс в ретро-стиле терминала
•	Прямое WebSocket-соединение с сервером (без Web Gateway)
•	Кнопки и действия: `Connect`, `Disconnect`, `Export .enc`, `Import .enc`
•	Формат сообщений: поле `To` (адресат `@nickname`) и поле ввода текста
•	Аппаратная криптография в браузере (Web Crypto API + `@peculiar/x509`)
•	Хранение закрытого ключа и сертификата в `localStorage`

#### 3.1.2 Модуль взаимодействия с БД

**Server Database Module** (`server/main.py`)
```python
class ChatServer:
    def _init_db(self)         # Создание таблицы certificates в PostgreSQL
    def _get_cert_from_db()    # Получение сертификата по nickname
    def _save_cert_to_db()     # Сохранение сертификата (правило 1 ник = 1 сертификат)
```

#### 3.1.3 База данных

**PostgreSQL Database: `chat_db`**

Таблица `certificates`:
```sql
CREATE TABLE certificates (
    nickname VARCHAR(255) PRIMARY KEY,
    cert_pem TEXT NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);
```

#### 3.1.4 Бэкенд

**WebSocket Chat Server** (`server/main.py`)
- Многопоточная обработка WebSocket-клиентов
- Встроенный корневой удостоверяющий центр (Private Root CA)
- Challenge-Response авторизация (nonce + RSA-подпись)
- Маршрутизация зашифрованных E2E-сообщений
- Раздача статических файлов веб-клиента по HTTP

#### 3.1.5 Модуль сетевого взаимодействия

**Протокол передачи данных:**
```
WebSocket (текстовые фреймы JSON UTF-8)
```

**Типы пакетов:**
- `cert_enroll` / `cert_enroll_response` — выпуск сертификата
- `auth_init` / `auth_challenge` / `auth_proof` — авторизация
- `key_request` / `key_response` — обмен ключами
- `message` — E2E-сообщение
- `event` — системные события
- `error` — ошибки

#### 3.1.6 Функциональные модули

**Криптографический модуль:**
- Генерация RSA-ключей (2048 бит)
- Создание PKCS#10 CSR и подпись X.509 сертификатов
- Валидация сертификатов и проверка прав на никнейм
- E2E-шифрование (RSA-OAEP + AES-256-GCM)
- Challenge-Response подпись (RSASSA-PKCS1-v1_5)
- Экспорт/импорт зашифрованных профилей `.enc` (AES-GCM по паролю)

## 4. Описание основных модулей и функций

### 4.1 Server (`server/main.py`)

#### Класс `Packet`
```python
class Packet:
    VERSION = 1
    def to_dict()               # Сериализация пакета в словарь
    def to_json()               # Сериализация пакета в JSON-строку
    @classmethod from_dict()    # Десериализация из словаря
    @classmethod from_json()    # Десериализация из JSON-строки
    @staticmethod create_event() # Фабричный метод системных событий
```

#### Класс `ClientHandler`
```python
class ClientHandler:
    def start_listening()       # Основной цикл приёма фреймов от клиента
    def send_packet()           # Потокобезопасная отправка пакета
    def handle_packet()         # Диспетчеризация пакетов (enroll, auth, message, key)
    def disconnect()            # Корректное закрытие сокета и удаление из списков
```

#### Класс `ChatServer`
```python
class ChatServer:
    def __init__()              # Инициализация сокета, CA и подключения к БД
    def _init_ca()              # Загрузка/генерация корневого сертификата CA
    def _init_db()              # Инициализация схемы PostgreSQL
    def _get_db_connection()    # Получение активного коннекта к БД
    def _get_cert_from_db()     # Чтение сертификата по никнейму
    def _save_cert_to_db()      # Сохранение сертификата в базу данных
    def validate_client_certificate() # Проверка подписи CA, срока и CN
    def issue_client_certificate()    # Подпись клиентского CSR и проверка на дубликат
    def verify_client_signature()      # Проверка подписи nonce открытым ключом
    def get_online_users()       # Получение списка активных пользователей
    def send_to_user()           # Маршрутизация пакета конкретному клиенту
    def broadcast()              # Широковещательная рассылка событий
    def _process_http_request()  # HTTP-сервер для статики веб-клиента
    def start()                  # Запуск WebSocket-сервера в основном потоке
    def stop()                   # Корректная остановка сервера и клиентов
```

### 4.2 Web Client (`client/app.js`, `client/index.html`)

#### Модуль `client/app.js`
```javascript
loadOrGenerateKeys(nick)         // Загрузка ключей из localStorage или генерация новой пары с CSR
connectChat()                    // Установка WebSocket-соединения с сервером
disconnectChat()                 // Разрыв соединения и сброс статуса
sendPacket(packet)               // Отправка JSON-пакета по открытому сокету
handlePacket(packet)             // Обработка входящих пакетов сервера (challenge, enroll, msg)
updateUsersList(text)            // Обновление списка онлайн-пользователей в UI
sendMsg()                        // Подготовка к отправке (запрос ключа при необходимости)
sendEncryptedMessage(to, text)   // E2E-шифрование: AES-256-GCM + RSA-OAEP
handleIncomingMessage(packet)    // Расшифровка сессионного ключа и тела сообщения
exportCrt()                      // Парольное шифрование ключей в файл .enc (AES-GCM)
handleImportFile(event)          // Расшифровка файла .enc по паролю и запись в localStorage
```

#### Разметка `client/index.html`
- Включает контейнер терминального окна, поля ввода `host`, `port`, `nickname`, кнопки `Connect`, `Disconnect`, форму отправки сообщений, журнал `log` и ссылки на внешние скрипты `x509.js` и `app.js`.
